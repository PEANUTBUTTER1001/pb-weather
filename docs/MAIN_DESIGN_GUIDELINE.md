# 메인 UI/UX 디자인 지침 (Anti-Slop Execution Spec v5.2)

> **원칙**: 품질 하한(`[하한]`)과 5대 슬롭 금지선(§5)만 엄격히 준수하고, 시각·공간·조형 기법(`[개방]`)은 금지 없이 제품 목적에 맞게 자율 설계한다.
> **실행**: 문맥에서 목표 플랫폼·도메인을 파악해 `Gate 1 → 생성 → Gate 2`를 자동 완주한다. 치명적 충돌 외 질문은 생략하고 미정 사항은 `[가정]`으로 명시하며, 단순 질문에는 답변만 제공한다.

## 0. 적용 우선순위와 강도 태그

- **우선순위**: `1. 사용자 명시 요구 · 제품 본래 플랫폼/도메인 목적` > `2. 프로젝트 세부 지침` > `3. 본 지침` (`[하한]`은 상시 유지, 도메인 목적을 해치는 기존 보일러플레이트 토큰은 확장·보완 허용)

| 태그 | 의미 | 적용 방식 |
|---|---|---|
| `[하한]` | 품질 바닥: 명암비·접근성·6대 극단 상태·실동작·기능 보존·데이터 정직성·§5 슬롭 금지선 | 이탈 불가. 위반 시 즉시 수정 후 재검증 |
| `[기본]` | 플랫폼·도메인 표준 참고치 | 강제 아님. 목적과 컨셉에 따라 자유 변경 |
| `[개방]` | 시각·공간 창의 영역: 레이아웃·표면·깊이·색상·그라데이션·서체·데이터 시각화·모션 | 제품 성격에 맞게 자율 결정 |

## 1. 실행 워크플로우 · 산출물 계약 · Gate 1 (`[하한]`)

Gate 1·Gate 2 보고는 본 앱 UI 화면에 렌더링하지 않고 채팅 응답(단일 파일 단독 출력 시 코드 주석)으로 분리한다.

| 실행 모드 | 규모 | 필수 산출물 계약 |
|---|---|---|
| **1. 분석 · 구조 설계** | **Full** | ① Gate 1 6항목 ② 정보 구조(IA)·영역 우선순위·시각 컨셉 근거 ③ 6대 극단 상태 표 ④ `[가정]` 목록 및 Gate 2 감사 |
| **2. 프로토타입** | **Full** | ① Gate 1 브리프 ② 라이트·다크 토큰 기반 핵심 여정 실동작 화면 ③ 도메인 콘텐츠·데이터 시각화 ④ 본 UI를 침범하지 않는 6대 극단 상태 전환 수단 ⑤ 좁은 화면 폭·글꼴 확대 리플로 대응 ⑥ Gate 2 감사 |
| **3. 구현 설계 · 코드** | **Full** | ① Gate 1 브리프 ② 테마·도메인 토큰 매핑 ③ 컴포넌트 트리 및 상태·시각화 계약 ④ 비동기·복구·접근성 구현 ⑤ Gate 2 감사 |
| **4. 부분 개선** *(기존 UI 수정 기본값)* | **Lite** | ① 변경 의도 1줄 ② 변경 영역 한정 수정 및 기존 기능·상태·API 계약 보존 ③ 범위 밖 개선점은 목록 제안만 ④ 영향 범위 Gate 2 감사 *(다중·골격 변경 시 Full 적용)* |
| **5. 전면 재설계** *(명시 요청 시)* | **Full** | ① 기존 UI 사전 감사 ② 보존할 기능·상태·데이터·API 계약 목록 ③ Gate 1 브리프 ④ 전면 재설계 코드 ⑤ 전/후 Gate 2 비교 감사 |

### Step 1. 생성 전 필수 선언 — Gate 1 (Full 규모 `[하한]`, 각 1줄)
1. **목표 제품 형태 & 실행 모드**: 목표 제품의 본래 플랫폼 형태와 최적 뷰포트·셸 구조 × 실행 모드
2. **핵심 작업 & 플로우**: 첫 화면에서 즉시 판단·실행할 핵심 행동과 `진입 → 실행 → 피드백/복구 → 복귀` 여정
3. **정보 위계 3단**: 1차 주 작업·핵심 정보 / 2차 흐름·비교·보조 맥락 / 3차 조건부 상세 노출
4. **공간 골격 & 슬롭 방지 주안점**: 채택한 레이아웃 구조와 집중 배제할 슬롭 결함(§5) 1줄
5. **시각 컨셉**: 시선 경로, 전경-배경 분리 방식, 색상·데이터 표현·타이포 방향
6. **극단 상태 조건**: 6대 극단 상태(§4.2)의 도메인별 처리 기준

## 2. 공통 물리 · 조판 원칙

플랫폼별 뷰포트·내비게이션·셸 구조는 목표 제품 성격에 맞게 자율 추론하되, 아래 물리적 가독성·조작성 바닥은 공통 준수한다.

| 항목 | 설계 지시 기준 | 강도 |
|---|---|---|
| **가독 명암비** | 모든 배경(그라데이션·이미지·다크 테마 포함) 위에서 본문·핵심 아이콘·조작 경계·포커스 윤곽선이 묻히지 않는 선명한 명암 대비 확보 (단, 내부 보조 구분선은 시각 노이즈가 되지 않게 은은한 톤으로 조율) | `[하한]` |
| **히트 타겟 & 안전 영역** | 오탭 없는 충분한 터치·포인터 히트 영역과 요소 간 간격을 확보하되, 보조 텍스트 버튼·칩·세그먼트의 시각적 박스는 과도한 여백으로 부풀리지 않고 텍스트에 맞게 조밀하게 패딩(터치 영역은 행 높이·외부 여백으로 확보) / 모바일·풀스크린 `dvh` 및 `safe-area` 여백 확보 | `[하한]` |
| **리플로 & 확대 내성** | 좁은 화면 폭 및 글꼴 확대 환경에서 정보·시각 지표의 임의 은닉·잘림·조작 불가·비의도적 2차원 스크롤 없이 조화로운 비례 스케일링과 열 재배치로 대응 — 표·차트·타임라인 내부 가로 스크롤은 허용 | `[하한]` |
| **깜빡임 / 모션 / 온보딩** | 과도한 점멸·시각 자극 배제 `[하한]` / 작업 흐름을 지연시키지 않는 즉각적 피드백 모션과 간결한 진입 단계 `[기본]` | `[하한]` / `[기본]` |
| **여백 리듬 & 행간** | 일관된 여백 리듬 기본 / 긴 읽기 본문은 여유 있는 행간을 두되, UI 컴포넌트·라벨·데이터 행·대형 타이틀·수치는 줄 간격이 느슨해지지 않도록 타이트한 행간으로 조밀하게 조판 | `[기본]` |

## 3. 공간 · 표면 · 데이터 · 조형 설계 원칙 (`[개방]`)

특정 레이아웃이나 컴포넌트 형식을 고정 강제하지 않는다. 제품의 도메인과 컨셉에 맞춰 아래 조형 원리를 자율 적용한다.

1. **공간 골격과 시선 흐름**: 첫 화면에서 핵심 정보나 주 작업이 즉시 보이도록 시선 초점을 잡고, `1차 핵심 → 2차 흐름·비교 → 3차 보조 상세` 순으로 시선이 자연스럽게 흐르도록 화면을 배치한다.
2. **전경-배경 분리와 표면 깊이**: 바닥 배경과 콘텐츠 표면이 한눈에 구분되도록 부유 카드·확산 그림자·토널 명도 차·평면 구분선·공간 오버랩 중 제품 성격에 맞는 표면 문법을 선택·조합한다.
3. **데이터의 시각적 형태화**: 추세·분포·비율·비교가 중요한 데이터는 단순 텍스트 나열에 그치지 않고 데이터의 성질이 직관적으로 드러나는 실제 값 비례 기하학적 시각화나 정밀 표로 표현하며, 중요도가 낮은 반복 노이즈는 절제한다.
4. **팔레트 개방과 테마 일관성**: 단색·다중 그라데이션·데이터 연동 색상·블러 등 모든 색채 기법을 열어두되, 기본 배경·표면·텍스트·구분선·상태색은 시맨틱 토큰으로 관리해 라이트·다크 테마 전환 시 일관성을 유지한다.
5. **아이콘·타이포 위계와 컨트롤 정돈**: 핵심 도메인 심볼과 UI 조작 아이콘의 시각적 비중을 구분한다. 메타·보조 텍스트는 작고 절제되게, 핵심 타이틀·수치는 선명한 굵기 대비로 조여 느슨한 텍스트 나열을 피하고, 옵션·설정 조작은 과대한 버튼 나열 대신 행 내부 인라인 컨트롤(세그먼트 등)로 단단하게 정돈한다.

## 4. 실동작 사용성 · 접근성 · 6대 극단 상태 (`[하한]`)

### 4.1 실동작 인터랙션 · 접근성 · 타이포 하한
- **인라인 피드백 & 섹션 독립 복구**: 로딩·중복 클릭 방지·완료·오류는 해당 조작이나 데이터 영역 내부에 인라인 표시한다. 부분 장애 시 정상 섹션은 그대로 유지하고 실패 섹션에만 원인과 즉시 실행 가능한 복구·대체 수단을 제공한다.
- **사용자 제어권 & 파괴적 액션 분리**: 모달·시트는 배경 잠금, `Esc`·배경 클릭 닫기, 닫은 후 호출 요소로의 포커스 복귀를 보장하며 탭·상세 전환 시 맥락을 유지한다. 파괴적 버튼은 일반 주요 버튼과 구분되는 위험색 분리 및 사전 확인 또는 실행 취소(Undo)를 제공한다.
- **접근성 & 키보드 무결성**: 상태·등급·오류는 색상 단독 표시를 금하고 텍스트·아이콘·기호를 병기한다. 텍스트 없는 모든 아이콘 버튼·그래픽에 `aria-label`을 부여하고, 전 조작 요소의 키보드 도달과 `:focus-visible` 포커스 윤곽선, 폼 `<label>`·`aria-invalid` 연결, 비동기 상태의 `aria-live` 알림을 보장한다.
- **타이포 정렬 · 줄바꿈 · 감속 모션**: 비교·목록·차트·시각 숫자에 `tabular-nums`, 한글에 `word-break: keep-all` 및 `overflow-wrap: anywhere`를 적용하고, `prefers-reduced-motion: reduce`에서 비필수 모션을 비활성화한다.

### 4.2 6대 극단 상태 내구성 (`[하한]`)
1. **최장 문구 · 긴 값**: 줄바꿈과 행 높이 확장으로 텍스트 잘림·요소 겹침 0건.
2. **빈 상태**: 무데이터·검색 결과 0건 시 원인과 다음 행동 버튼 제시.
3. **로딩 · 백그라운드 갱신**: 최초 로딩은 스켈레톤으로 레이아웃 시프트를 방지하고, 캐시 보유 갱신은 기존 화면을 유지한 채 진행 표시만 노출.
4. **오류 · 부분 실패 · 결측**: 오프라인·한도 초과 시 캐시 데이터와 수신 시각을 표시하고, 부분 실패나 결측 구간은 해당 영역만 인라인 안내 및 재시도·대체 경로 제공.
5. **권한 거부 · 기능 꺼짐**: 앱 멈춤 없이 사유 안내 및 수동 검색·입력 대체 경로로 즉시 연결.
6. **좁은 화면 폭 & 글꼴 확대**: 정보·시각 지표의 임의 은닉 없이 조화로운 비례 스케일링과 열 재배치로 가로 넘침·잘림 0건.

## 5. 핵심 슬롭 금지선 — 최소 정예 5조 (`[하한]`)

| # | 금지하는 슬롭 결함 (`[하한]`) | 충족해야 할 설계 기준 |
|---|---|---|
| **1** | **붕어빵 클론 박스 도배**: 중요도와 성격이 다른 모듈을 동일한 박스 형태로만 단순 반복 타일링·적재 | **위계별 조형·스케일 차등**: 1·2·3차 정보의 역할과 데이터 성격에 맞게 면적, 타이포 스케일, 시각 표현 형식을 다르게 설계해 시선 초점 형성 |
| **2** | **전경-배경 미분리 및 다중 박스 과잉 중첩**: 바닥 배경과 표면 구분이 없거나 박스 안에 서브 박스를 중첩 남발해 여백 잠식 | **명확한 Figure-Ground 대비 & 단일 계층 구획**: 바닥과 콘텐츠 표면을 명확히 분리하고, 컨테이너 내부 하위 요소는 중첩 박스 없이 여백·정렬·구분선으로 정리 |
| **3** | **시각화 없는 숫자 줄글 방치 & 먹통 컨트롤**: 추세·범위·비율 데이터를 줄글로만 나열하거나 작동하지 않는 가짜 컨트롤 배치 | **데이터 형태화 & 100% 실동작**: 시각적 직관이 필요한 데이터는 실제 값에 비례하는 기하학적 형태와 결합하고, 화면의 모든 조작·선택 변경 시 연관 데이터와 화면이 일관되게 연동되어 작동 |
| **4** | **가독성 침해 & 한글 1글자 줄바꿈·자릿수 흔들림**: 배경에 글자가 묻히거나 한글이 1글자씩 쪼개지고 숫자 열이 흔들림 | **절대 가독성 & 타이포 무결성**: 모든 배경 위 선명한 명암 대비, 한글 `keep-all`, 수치 `tabular-nums`, 좁은 화면 폭·글꼴 확대 리플로 방어 충족 |
| **5** | **공허한 홍보 상투어·가짜 데이터 & 본 화면 침범 디버그 바**: 기능 화면에 무의미한 홍보 문구·가짜 통계를 넣거나 테스트 버튼으로 본 UI를 가림 | **즉각적인 도메인 진입 & 비침범 시뮬레이터**: 첫 화면에 핵심 도메인 정보와 주 작업을 즉시 배치하고, 모의 데이터는 `[예시 데이터]`로 명시하며 상태 전환 도구는 본 UI와 분리 |

## 6. 출력 전 자체 감사 — Gate 2 (`[하한]`)

적용 범위(§1)에 대해 아래 10개 항목을 **`통과` / `실패` / `해당 없음` / `미확인`**으로 판정하고, `[하한]` 실패 시 수정 후 재검증한다.

| 코드 / 구조 | 검사 항목 | 판정 기준 |
|---|---|---|
| **A1** `[기본]` | **테마 토큰 & 다크 모드** | 기본 배경·표면·텍스트·구분선·상태색의 시맨틱 토큰 정의 및 라이트·다크 전환 일관성 |
| **A2** `[하한]` | **전경-배경 분리 & 과잉 중첩 0건** | 바닥 배경과 표면의 명확한 분리 및 컨테이너 내부 불필요한 서브 박스 중첩 0건 |
| **A3** `[하한]` | **가독 명암비 & 파괴적 액션 분리** | 모든 배경 위 텍스트·핵심 아이콘·조작/포커스 경계의 선명한 가독 명암 대비(보조 구분선은 은은하게 조율) 및 파괴적 버튼 분리 |
| **A4** `[하한]` | **접근성 레이블·포커스·색 비단독** | 아이콘 버튼·그래픽 `aria-label` 완비, `:focus-visible` 유지, 색 단독 상태 표시 0건, 폼 오류·`aria-live` 연결 |
| **A5** `[하한]` | **타이포·정렬·리플로·타겟·감속 모션** | 한글 `keep-all`, 수치 `tabular-nums`, 좁은 폭·글꼴 확대 시 은닉·잘림 없는 비례 리플로, 조밀한 버튼 패딩과 충분한 히트 영역, `prefers-reduced-motion` 분기 |
| **G1** `[하한]` | **목표 형태 & 시선 경로 일치** | Gate 1 목표 제품 형태·시각 컨셉 일치 및 `1차 핵심 → 2차 흐름 → 3차 보조` 시선 경로 확립 |
| **G2** `[하한]` | **클론 박스 도배 배제 & 위계 차등** | 균등 클론 박스 타일링 배제 및 정보 위계별 면적·타이포·조형 차등 설계 |
| **G3** `[하한]` | **데이터의 시각적 형태화** | 추세·범위·비율·비교 데이터의 실제 값 비례 기하학적 시각화 결합 및 불필요한 시각 노이즈 절제 |
| **G4** `[하한]` | **100% 실동작 플로우 완결성** | 먹통 컨트롤 0건, 조작·선택에 따른 연관 데이터 일관 연동 및 진입·조작·상세·취소·섹션 독립 실패 복구·복귀 여정 완결 작동 |
| **G5** `[하한]` | **6대 극단 상태 & 비침범 시뮬레이터** | 6대 극단 상태 완비, 홍보 상투어·가짜 데이터 0건, 비침범 상태 전환 수단을 통한 즉시 재현·복구 |

### Gate 2 보고 형식 (`[하한]`)
- **Lite**: 검사 대상·결과·미확인 사항 1~2줄 요약.
- **Full 프로토타입 · 구현 설계 · 부분 개선**: ① **감사 요약**(`A1~A5`, `G1~G5` 판정, 전원 통과 시 `All Pass`) ② **자체 수정 이력**(실제 수정한 결함이 있을 때만 기록) ③ **검증 한계**(정적 확인과 렌더링 확인 구분 및 `[가정]` 명시).
- **Full 분석 · 전면 재설계 (또는 전체 표 요청 시)**: `A1~A5`, `G1~G5` 항목별 판정과 근거 1줄을 표로 출력.

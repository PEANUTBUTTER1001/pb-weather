# SECURITY_PRIVACY.md

## 1. 보안 범위

- 대상: 안드로이드 날씨 앱 v1(클라이언트 단독, 자체 서버 없음).
- 관련 요구사항: SEC-001(위치정보 최소 처리), SEC-002(서비스 키 보호), DATA-001(로컬 저장), DATA-002(출처 표기).
- 계기: Wizard 제약 답변 — 개인정보(위치) 처리, 운영 인력 적음, 사용자 집중 가능성.
- 제외: 사용자 계정·결제·서버 측 보안(해당 기능 없음).

## 2. 보호 대상 자산

| 자산 | 위치 | 민감도 |
| --- | --- | --- |
| 기기 현재 위치(위경도) | 메모리(변환 중) | 높음 — 개인위치정보 |
| 즐겨찾기 지역·대표 위치 | DataStore | 중간 — 생활 반경 추정 가능 |
| 날씨·과거 자료 캐시 | Room | 낮음 — 공개 데이터 |
| 공공데이터포털·에어코리아 서비스 키 | BuildConfig(APK 내) | 중간 — 오남용 시 한도 소진·키 차단 |
| 릴리스 서명 키(keystore) | 개발자 PC, Git 제외 | 높음 — 유출 시 앱 위장 업데이트 가능 |

## 3. 신뢰 경계

1. **기기 ↔ 공공 API**: HTTPS. 전송 값은 격자(nx, ny)·지점 ID·TM 좌표·측정소명. 원본 위경도 미전송.
2. **앱 ↔ Play services location**: OS 권한 경계, COARSE만 요청.
3. **앱 ↔ 저장소(Git)**: 키·keystore는 경계 밖(로컬 파일, .gitignore).
4. **앱 ↔ 위젯/Worker**: 같은 앱 프로세스, 동일 저장소 사용.

## 6. 인증

- 사용자 인증 기능 없음.
- API 인증: 공공데이터포털 서비스 키(쿼리 파라미터 `serviceKey`). OkHttp 인터셉터 단일 지점에서 추가.

## 7. 인가

- 앱 내부 권한 분리 없음(단일 사용자).
- OS 런타임 권한: `ACCESS_COARSE_LOCATION`만 요청, 요청 전 목적 안내 화면 표시, 거부 시 기능 축소(지역 검색)로 정상 동작.

## 8. 입력값 검증

- 지역 검색어: 길이 2~30자, 내장 DB LIKE 검색(파라미터 바인딩, 원시 SQL 조립 금지).
- 기간 입력: 종료일 ≤ 어제, 기간 ≤ 366일(FR-006).
- API 응답: resultCode·필드 타입 검증, 숫자 파싱 실패 시 결측(null) 처리, 크래시 금지.

## 9. 암호화

- 전송: HTTPS(TLS) 전용.
- 저장: 캐시 데이터는 공개 기상 데이터로 별도 암호화 불필요. 즐겨찾기는 앱 전용 저장소(샌드박스) 보관. 
- 백업: `android:allowBackup`은 데이터 추출 규칙으로 DataStore 즐겨찾기만 허용 여부 결정(구현 시 확정, 기본 false 권장).

## 11. 로그·비밀정보

- 로그: `Log` 직접 호출 대신 debug 전용 로거 래퍼, release에서 제거(R8 `-assumenosideeffects`).
- 금지 로그: 위경도, 서비스 키, 전체 요청 URL(쿼리 포함).
- 비밀정보 위치: `local.properties`(서비스 키), `keystore.properties`·`*.jks`(서명) — 모두 `.gitignore`.

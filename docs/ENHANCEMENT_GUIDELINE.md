## 4. ENH-001 자료 시각·출처·관측/예보 구분

### 4.1 목적·표시

- 해결 문제: 앱 수신 시각을 자료 생성 시각으로 오인하거나, 서로 다른 지역·시간·성격의 값을 같은 정보로 해석하는 문제.
- 벤치마크: Windy의 데이터 정보·관측소·모델 출처 안내. 기본 화면은 짧게, 상세에서 근거 확인하는 방식 계승.
- 각 섹션에 해당 자료의 시각·자료 성격 표시. 예: `기상청 실황 · 14:00 자료`, `기상청 예보 · 14:00 발표`, `에어코리아 · 13:00 측정`.
- 자료 상세에는 출처·발표 또는 관측 시각·예보 유효 시각·앱 수신 시각·지역 또는 측정소·오래됨·오프라인·오류 상태 표시.
- `방금 갱신`은 성공한 수신에만 사용. 값이 같은 응답이라도 실제 성공 수신 여부를 기준으로 수신 시각 처리.
- 현재 기온은 실황, 하늘상태가 예보에서 보완된 경우 해당 출처·유효 시각 구분. 서로 다른 자료를 모두 실황으로 표기 금지.
- 최근 10일 요약은 지표별 유효 자료 일수 명시. 결측 강수량을 0으로 바꿔 완전한 합계처럼 표시 금지.

| 상태 | 화면·메타데이터 |
| --- | --- |
| 유효 캐시 | 값과 원래 자료 시각 표시. 갱신 불필요 시 추가 요청 없음 |
| 만료 캐시·갱신 중 | 기존 값·자료 시각·오래됨·갱신 중 표시 |

| 캐시 있음·오프라인 | 마지막 값·자료 시각·오프라인 표시. 캐시 만료를 정상 최신 자료로 표현 금지 |

- AC-ENH-001-1: 섹션별 자료 시각·성격·출처를 실제 응답과 대조 가능.

## 5. ENH-002 위젯 갱신·대표 지역 일관성

### 5.1 동작

- 해결 문제: 위젯 무한 로딩, 실패 시 기존 값 소실, 삭제·전환한 대표 지역과 표시 지역 불일치.
- 벤치마크: 원기날씨·Today Weather의 반복 확인용 위젯과 대표 지역 사용 방식.
- 기본 위젯 구성은 프로토타입 유지. 지역·현재 기온·하늘상태·오늘 최고/최저·마지막 성공 시각 표시.
- WorkManager 네트워크 제약·60분 주기 등록 유지. 정확히 매 정각 실행된다는 보장·문구 제외. 중복 주기 작업 등록 금지.
- 갱신 실패 시 마지막 성공 자료·시각 유지, 진행 상태 종료. 실패를 정상 갱신으로 처리 금지.
- 위젯 탭은 위젯의 대표 지역 홈으로 이동. 앱의 다른 선택 지역을 열어 지역 혼동 유발 금지.
- 대표 지역 변경은 앱 저장소 반영 → 해당 지역 캐시 표시 또는 로딩 → 위젯 갱신 순서. 이전 지역 값을 새 지역명 아래 표시 금지.
- 대표 즐겨찾기 삭제 시 남은 즐겨찾기의 저장 순서 첫 지역으로 전환. 남은 항목이 없으면 대표 미지정, 위젯에 `대표 지역 선택` 동작 표시. 앱의 일반 선택 지역은 별도 유지.
- 삭제 되돌리기는 기존 순서·대표 여부를 함께 복원. 서로 다른 지역의 연속 삭제·되돌리기도 상태 일치 필요.
- 앱에서 대표 지역 갱신 성공 시 동일 캐시로 위젯 반영. 화면 재구성마다 별도 API 요청 금지.

## 6. ENH-003 시간·일자 선택 상세

### 6.1 동작·데이터

- 해결 문제: 가로 목록·주간 행의 제한된 공간에서 필요한 지표를 한 시각·날짜 기준으로 확인하기 어려운 문제.
- 벤치마크: Windy의 동일 시간 지표 비교, Today Weather의 시간별·일별 상세 정보.
- 시간별 칸 선택 시 하단 상세 시트 표시. 선택 표시·기온 곡선·상세 값은 동일한 KST 시각과 지역 키 기준으로 동기화.
- 시간 상세: 날짜·시각·기온·하늘상태/강수형태·강수확률·예상 강수량·자료 출처·발표 시각. 응답에 없는 값은 `미제공`.

- 시간별 원자료가 실제 있는 구간만 시간 상세 연결. 중기 일자료를 임의로 시간별 보간하거나 종일 값을 오전/오후의 독립 예측처럼 복제 금지.
- 초단기·단기 병합은 항목별 처리. 우선 자료의 결측값이 다른 자료의 유효값을 삭제하지 않도록 처리.
- 강수량은 숫자·범위·정성값을 구분. `1mm 미만`, `30~50mm` 등을 단일 확정 숫자로 바꿔 저장·합산 금지.
- 시트는 기존 화면 스타일·공통 컴포넌트 재사용. 닫기·시스템 뒤로 가기 후 호출 항목의 위치·초점·스크롤 복원.
- 상세 열기만으로 캐시가 유효한 동일 요청 재호출 금지. 정상 캐시가 없으면 해당 상세의 로딩·오류만 표시.

## 7. ENH-004 예보 기반 한 줄 요약

### 7.1 생성 규칙

- 해결 문제: 숫자 목록을 모두 읽어야 가까운 시간의 날씨를 판단할 수 있는 문제.
- 벤치마크: TWC·AccuWeather의 일상 판단 중심 정보 제공. 본 앱은 실제 예보 값에 연결된 고정 문장 템플릿 사용.
- 홈 시간별 영역의 기존 보조 문구 위치 활용. 새 홈 카드·별도 탭·설정 추가 제외. 출처·발표 시각은 ENH-001 상세에서 확인 가능 상태 유지.
- 생성 대상은 현재보다 뒤의 최대 6개 실제 시간별 예보 항목. 빈 시각 임의 생성 금지.
- 해당 구간의 숫자 POP가 있는 항목 중 가장 큰 값을 선택, 동률이면 가장 이른 시각 선택. 해당 시각의 기온·강수량 중 제공되는 값만 문장에 사용.
- POP가 전부 결측이면 가장 이른 시각의 유효 기온으로 요약. 요약 가능한 값이 없으면 `예보 요약 자료 없음`과 해당 섹션 재시도 연결.
- 현재 화면의 지역·예보 버전·오래됨 상태에서 산출. 지역 전환 시 이전 요약 잔류 금지.
- 예: `15시 예보 · 강수확률 60% · 예상 강수량 1~4mm`. 예시는 문장 형식이며 실제 날씨 의미 아님.
- 시간별 최대 POP를 하루 전체 강수확률로 표현 금지. `15시 비 시작`, `우산 불필요`, 근거 없는 활동·안전 점수 생성 제외.
- 어제 비교 문구는 기존 비교 영역 유지. 오늘 최고·최저는 예보, 어제 값은 ASOS 관측임을 병기. 서로 다른 날짜의 평균·일강수량을 1시간 실황으로 대체 금지.

## 8. ENH-005 미세먼지 최근 측정 추이

### 8.1 조회·정규화

- 해결 문제: 현재 PM10·PM2.5 수치만으로 최근 변화 방향을 확인하기 어려운 문제.
- 벤치마크: 미세미세의 시간별 농도 확인·수치와 등급 병행.
- 홈 히어로 최하단 구분선 아래 통합된 PM10·PM2.5 컴팩트 2열 띠(하단 별도 카드 제거) 선택 시 상세 시트 오픈. 기본 홈의 PM10·PM2.5 2열 구성·측정소/측정 시각/확정 전 안내·섹션 독립 오류/측정소 대체 유지.
- 기존 측정소별 실시간 측정 API 사용. `dataTerm=DAILY`, `numOfRows=24`, `pageNo=1`, `returnType=json`을 기본 요청으로 사용. 오퍼레이션 버전은 구현 시 공식 명세·실응답으로 고정.
- 기존 최신 값 조회와 최근 측정 목록 요청 통합 우선. 이미 받은 최신 응답에서 최대 24개 실제 항목 활용, 단순 시트 재진입으로 동일 자료 중복 호출 금지.
- 정규화 키는 측정소·측정 시각. 시각 오름차순 정렬·중복 제거, 원본 측정소·자료 상태 보존.
- 제공 항목이 24개 미만이면 실제 개수·시작/종료 시각 표시. 시각의 연속성·정확한 24시간 분량 보장 금지.
- `24:00` 등 기관 시각 표현은 다음 날짜 `00:00`으로 정규화하되 출처와 대응 가능 상태 유지. 파싱 불가 항목은 제외 사유 기록, 비밀·좌표 로그 금지.
- PM10·PM2.5는 독립 결측 처리. `-`·점검·장비 오류·음수·파싱 불가는 0으로 바꾸지 않음.

### 8.2 표시·캐시

- 제목은 `최근 측정 추이`. 농도 단위 `µg/m³`, 측정소·기간·측정 시각·비확정 자료 안내 표시.
- 두 지표를 구분하는 범례·선 또는 막대와 항목별 상세 제공. 결측 구간의 선을 끊고, 측정소 변경 구간을 단일 연속 관측처럼 연결 금지.
- 현재 값·등급은 동일 측정 시각·동일 시간 기준으로 연결. 1시간 등급 필드와 24시간 등급 필드 혼용 금지. 선택 기준·버전을 상세에 표시.
- 측정소 대체 시 최신 값과 추이의 출처 일치. 다른 측정소 이력을 보여줄 경우 명칭·기간을 별도 구획으로 구분.
- 측정소별 목록을 Room 기반 기존 AIR 캐시와 통합, 기본 만료 1시간 유지. 지역→측정소 연결도 복원 가능 상태로 보관, 원본 사용자 좌표 저장 금지.
- 오프라인·오류 시 마지막 목록·자료 시각·오래됨 상태 표시. 목록 없음은 빈 상태·재시도 제공.
- 미래 농도 예측·WHO 등급 전환·건강 행동 지수 추가 제외.

- AC-ENH-005-1: 24개·부분 목록·중복·역순·자정·`24:00`·PM별 결측을 정상 처리.

## 9. ENH-006 계산 체감온도

### 9.1 성격·입력·정책

- 해결 문제: 기온 외 습도·풍속의 영향을 함께 파악할 보조 지표 부족.
- 벤치마크: 상용 앱의 체감온도 보조 지표. 본 앱은 공개 산출식을 적용한 `계산 체감온도`로 명명, RealFeel 또는 기상청이 직접 제공한 공식 체감온도 값으로 표시 금지.
- 홈 현재 날씨의 보조 지표에 배치, 선택 시 적용식·입력값·단위·자료 시각·적용 범위·계산 한계 표시. 현재 기온의 시각적 우선순위 유지.
- 같은 격자·실황 시각의 `T1H(℃)`, `REH(%)`, `WSD(m/s)` 사용. 서로 다른 시각의 값으로 결측 보충 금지.
- 계절은 KST 자료 시각의 월 기준. 5~9월 습도식, 10~다음 해 4월 풍속식. 경계월 자동 혼합·수식 평균 처리 제외.
- 겨울 표시 조건: `Ta <= 10℃`, `windMs >= 1.3m/s`, 유효 풍속. 음수·결측·NaN·무한값은 산출 불가.
- 여름 표시 조건: 앱의 보수적 적용 범위를 `0 <= Ta <= 50℃`, `5 <= RH <= 99%`로 제한. Stull 근사식의 문헌 범위에서 저온·저습 조건을 더 제한한 앱 정책이며 공식 서비스 전체 적용 범위라는 뜻 아님.
- 조건 미충족은 `적용 범위 밖`, 필요한 입력 결측은 `자료 부족`. 원래 기온을 체감온도처럼 대신 표시하거나 임의 보정 금지.
- WSD의 평균시간·관측 정의는 구현 전 해당 API 공식 가이드로 확인·기록. 겨울식의 10분 평균풍속 입력과의 대응을 확인하지 못하면 `입력 규격 미확인`으로 처리. 다른 평균시간을 동일 입력이라고 단정 금지.

### 9.2 산출식

기호: `Ta`는 기온 ℃, `RH`는 상대습도 퍼센트값(70%는 70), `V`는 km/h. `atan`은 라디안, 내부 계산은 부동소수점 원정밀도 유지. 최종 표시만 HALF_UP 반올림으로 소수 첫째 자리까지 표시, 음의 0은 0으로 정규화.

```text
V = windMs * 3.6
겨울 = 13.12 + 0.6215*Ta - 11.37*V^0.16 + 0.3965*Ta*V^0.16

Tw = Ta*atan(0.151977*sqrt(RH + 8.313659))
     + atan(Ta + RH) - atan(RH - 1.67633)
     + 0.00391838*RH^1.5*atan(0.023101*RH) - 4.686035
여름 = -0.2442 + 0.55399*Tw + 0.45535*Ta
       - 0.0022*Tw^2 + 0.00278*Tw*Ta + 3.0
```

| 산식 확인 예시 | 반올림 전 참고값 | 표시값 |
| --- | --- | --- |
| 겨울, Ta=-10℃·풍속=5m/s | 약 -17.446593℃ | -17.4℃ |
| 여름, Ta=30℃·RH=70% | Tw 약 25.595662℃, 체감 약 31.289416℃ | 31.3℃ |
| 겨울, Ta=10℃·풍속=1.3m/s | 약 9.855959℃ | 9.9℃ |

- 위 예시는 문서 작성 시 수식 계산 확인 결과. 제품 코드 테스트 실행·실제 날씨 관측·공식 API 체감온도 검증 결과 아님.
- 근거: [기상청 체감온도 산출식·계절·풍속 조건](https://data.kma.go.kr/climate/windChill/selectWindChillChart.do), [Stull 2011 습구온도 근사식·적용 한계](https://doi.org/10.1175/JAMC-D-11-0143.1).

### 9.3 수용 기준

- AC-ENH-006-1: 수식 예시·풍속 단위 변환·RH 퍼센트 입력·계절 경계·적용 범위·결측·비정상값 테스트 통과.
- AC-ENH-006-2: 화면 계산값과 상세 입력·수식·시각 일치. 공식 제공값·독점 지표·일 최고/최저 체감온도로 오인시키는 문구 없음.
- AC-ENH-006-3: 입력 계약 확인과 실제 유효 자료를 이용한 계산·표시 확인. 기능을 숨기거나 전 구간 산출 불가인 상태만으로 완료 판정 금지. 계절별 화면은 통제된 테스트 데이터로 보완 검증.

## 12. 최종 완료·제외 범위

- 완료 조건: 기존 범위 중 2절에서 확정 변경한 내용 반영 + ENH-001~006의 모든 AC 검증 + 위 TEST 12개 실제 PASS 증거 + S25 Ultra 실 API 작동 확인.
